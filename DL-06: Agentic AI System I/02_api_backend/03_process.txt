### 02_api_backend — Process & Techniques (README)

Overview
--------
This is the Backend/API layer that acts as a gateway between the Web App and the entire AI
system. It is responsible for authentication, request validation, file processing, and managing
user context/history, then forwarding the work to the AI Router.

Architecture
------------
- Built as a RESTful API with FastAPI (async), to handle many concurrent requests without
  blocking the thread while waiting for the AI Router to respond.
- Split into layers: Router (endpoint) → Service (business logic) → Repository (database access),
  following separation of concerns, to keep the code easy to test and maintain.

Techniques Used
----------------
- JWT-based Authentication: stateless auth, good for a system with multiple services (scales easily).
- Redis caching: stores short-term session/context to reduce repeated database queries
  (e.g. the last 10 messages of a conversation).
- Async I/O: uses async def together with httpx.AsyncClient when calling the AI Router,
  so one request doesn't block others.
- File processing pipeline runs as a separate worker/queue (e.g. FastAPI background tasks,
  or Celery for large/slow files), so the main API doesn't time out.
- Structured logging (JSON logs) makes it easy to feed into the Monitoring stack
  (see 08_monitoring_deployment).

Database Schema (concept)
---------------------------
- users(id, email, name, role, created_at)
- conversations(id, user_id, session_id, created_at)
- messages(id, conversation_id, role, content, sources_json, created_at)
- uploaded_files(id, user_id, filename, extracted_text, uploaded_at)

Things to Watch Out For
--------------------------
- Sanitize/escape input before saving to the database (protect against SQL injection even with an ORM).
- Limit uploaded file size (e.g. max 10MB) and set a timeout for file processing.
- Use a circuit breaker/retry policy when calling the AI Router, to handle the case where it is down.
- Keep secrets (JWT key, DB credentials) in environment variables, never hardcoded in the code.
